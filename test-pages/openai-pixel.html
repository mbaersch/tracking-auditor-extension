Consent is stored as denied. The SDK drops every event before it reaches the network — nothing will show up in a debugger, no matter which button you press. The state lives in localStorage["oaiq_consent"] and the __oaiq_consent cookie and survives reloads, so removing ?consent=denied from the URL is not enough.

Page variants (reload)

Consent has to be decided before init, so those cases are page loads, not buttons. Without consent the SDK posts a stripped body (events only) with credentials: "omit". The oppref variant seeds the first-party __oppref cookie the way an ad click would.

Batching

The SDK flushes 1 s after the last event, at the latest 4 s after the first — a burst lands as one POST with ec=3, the spread version as three.

Automatic advanced matching

When AAM is enabled for the account, the SDK scrapes these fields, normalizes and SHA-256-hashes them in-browser and sends them under user.fm / user.js / user.ht — as opposed to user.in for what init was given. The form uses a second identity on purpose: a scraped value whose hash matches one already passed to init is dropped as a duplicate, leaving user.fm empty.
